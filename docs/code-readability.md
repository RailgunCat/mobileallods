# Имена восстановленных данных

В логике Godot используются имена из
`godot/scripts/gameplay/game_ids.gd`: `Stat.HP`, `Stat.ARCHERY`,
`Spell.FIRE_ARROW`, `ScriptOp.RECRUIT`, `QuestState.COMPLETED`,
`StoryScript.BAT_DEFEATED`, `Facing.RIGHT` и другие.
Числовые значения здесь нужны для совместимости с таблицами JAR.

Эти имена восстановлены нами по поведению кода и данным. Декомпилированный
клиент не сохраняет исходные имена. Часть чисел могла быть `static final`
константами, встроенными компилятором; утверждать, что в исходниках существовали
именно наши Java enum, нельзя. Неопределённые коды оставлены как `UNKNOWN_19`…
`UNKNOWN_22`, без придуманного назначения. Названия групп школьных колонок
`LIGHT_*`/`DARK_*` отражают их использование в полезной нагрузке заклинаний.

Пример чтения новой логики:

```gdscript
if actor.stats[Stat.MANA] >= Spells.cost(actor, Spell.FIRE_ARROW, definitions):
    battle.cast(Spell.FIRE_ARROW, target.cell)
```

Данные также получили именованные поля:

- `spell_definitions`: `base_mana`, `base_power`, `school_stat`, `rank_step`.
- Инструкции сцен: `operands` с именами аргументов вместо `args[0]`/`args[1]`.
- `legacy_scene_data.gd`: единственная граница декодирования исходных записей
  NPC и прямоугольников триггеров; дальше используются `story_group`, `left`,
  `right`, `encounter_enabled` и другие поля.
- Состояние сессии: `quests`, `triggers`, `spawn_states`, `tutorial_seen`;
  событие смерти доступно через `actor.death_script`.
- Награды: `base_experience`, `minimum_gold`, `maximum_gold`.
- Экономика: определения вещей с `hero_type`, `socket_count`, `unlock_progress`;
  тайники с `pickup_id`, `items`, `gold` и `script_id`.
- Гнёзда: `sockets` хранят совместимые определения, `socket_instance_ids`
  сохраняют конкретные экземпляры кристаллов при вставке/извлечении.
- Переходы: `location_id` — номер из Java (обычные карты с 0, подземелья
  отрицательные), `entry_id` — точка входа. В подписи/файле карты обычный номер
  увеличен на 1. В генераторе поля комнаты названы `Room.LEFT`, `Room.EXIT`,
  `Room.LOOT`, `Room.REACHED` и другими enum-именами.
- Снимок `build/gameplay-snapshot.json`: `stats_by_name` и `base_stats_by_name`
  рядом с совместимыми числовыми массивами.

57 характеристик хранятся в `PackedInt32Array`, чтобы сохранить порядок таблиц,
целочисленные формулы и прямое сравнение с Java. При обращении используется
`Stat`, а номера сосредоточены в описании формата. Исходные `values`, `args`
и `action_table` сохранены для проверки и обратной сборки JAR. Сырые таблицы
редактируются в `analysis/extracted/`, затем выполняется `export-godot`;
именованные поля экспортёр вычисляет заново из этих данных.

Обычные координаты, коэффициенты формул, позиции в очереди и индексы тестовых
примеров остаются числами. Они не являются скрытыми кодами характеристик.

## Общая логика

- `inventory_rules.gd`: `available()` отбирает предметы для инвентаря и продажи,
  исключая кристаллы в гнёздах; фильтр героя допускает его снаряжение и свободные
  кристаллы. `preview_stats()` считает примерку или снятие без изменения героя.
  Порядок, подписи и набор строк сравнения остаются в соответствующем экране.
- `legacy_theme.gd`: подготовка пикселей шрифта, координаты глифов и создание
  затемнения мира; `world_shade.gdshader` используется меню и боевыми заставками.
- `legacy_map_view.gd`: общие проходы фоновой текстуры, теней и сетки для
  обычных карт и подземелий. Специфические слои подземелий остаются в игровом виде.
- `java_reference.py`: извлечение Java-метода и запуск подготовленного эталонного
  стенда. Формулы стендов не зависят от реализации Godot.

`legacy_management.gd` обслуживает игровые экраны персонажа, инвентаря и журнала.
`management_panel.gd` сохраняется для отладки и показа добычи; общие правила
инвентаря используются обоими интерфейсами.
